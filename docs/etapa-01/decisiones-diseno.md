Decisiones de diseño

1. Gestión de clientes
Se decidió registrar los meseros en una entidad independiente para evitar repetir sus datos en cada venta. Cada meseros tendrá un identificador único y sus datos podrán ser registrados, modificados y consultados. Las ventas estarán asociadas a un mesero para poder consultar posteriormente su historial de operaciones.

2. Gestión de stock y recetas
Se decidió contemplar el stock tanto de productos como de ingredientes. Para los productos que requieren elaboración, se podrán registrar recetas indicando los ingredientes utilizados y sus cantidades.

3. Usuarios y roles
Se decidió implementar usuarios y roles para identificar quién realiza cada operación y limitar el acceso a determinadas funciones del sistema. De esta manera, una venta podrá quedar asociada al usuario responsable de registrarla.

4. Alcance del proyecto
Se decidió mantener el sistema limitado a las operaciones principales de gestión del bar. Por este motivo, no se incluirán funcionalidades como facturación electrónica, gestión de sueldos, contabilidad completa, delivery o integración con plataformas externas.

5. Historial y reportes
Se conservarán las ventas realizadas para permitir consultas posteriores sobre el historial de operaciones y los precios utilizados. A partir de esta información se podrán generar reportes básicos para facilitar la consulta y el control de las operaciones del bar.
